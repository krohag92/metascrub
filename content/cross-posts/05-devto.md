When a document arrives claiming to prove something important, the metadata often has something to say too.

## What Hides in a Leaked DOCX

A DOCX file is a ZIP archive. Inside is a folder of XML files. Three of them contain metadata that survives almost every editing step:

**`docProps/core.xml`** — creator name, last editor, revision count, creation and modification timestamps.

**`docProps/app.xml`** — the application used, the version, and the company name registered in the Office install.

**`word/document.xml`** — tracked changes with author names and individual edit timestamps. Also: embedded images, each potentially carrying GPS coordinates.

This structure means that a DOCX not only records who wrote it, but often records every person who edited it and roughly when each edit occurred.

## What Hides in a Leaked PDF

PDF metadata splits between two structures:

- **Info dictionary**: `Producer`, `Creator`, `Author`, `CreationDate`, `ModDate`
- **XMP packet**: more verbose version of the same fields, plus `DocumentID` and `InstanceID` GUIDs

The `Producer` field is frequently the most useful: it records which application generated the PDF. A document claiming to be from one source, but whose `Producer` says it was generated by a different application, is worth investigating.

## A Well-Documented Case

The 2002 UK "Iraq dossier" case illustrates how metadata forensics intersects with journalistic investigation. The `lastModifiedBy` and tracked changes fields pointed to Downing Street communications staff, while a textual comparison showed verbatim copying from a postgraduate student's thesis without attribution.

## Forensic Workflow with MetaScrub

```bash
npm install -g metascrub

# Capture metadata before opening in any application
metascrub view --json leaked.pdf > forensic-log.json

# Compare two versions of the same document
metascrub compare version-a.docx version-b.docx

# Batch-process a large leak
metascrub batch ./leak-folder/ --format json > all-metadata.json
```

The compare command flags fields that changed between versions and fields that are present in one file but absent in the other. A revision counter that reset to 1 suggests the text was copy-pasted into a new document to discard the history.

## Limits of Metadata Forensics

- Metadata can be altered. Plausible-looking metadata is not proof of authenticity.
- Timestamps reflect device clocks, which can be wrong.
- Different tools surface different fields. Use more than one on high-stakes documents.
- Stripped metadata is itself a signal — note it in your forensic log.
