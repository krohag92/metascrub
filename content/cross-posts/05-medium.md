When a document arrives in a journalist's inbox claiming to prove something important, experienced investigators don't read the document first. They check the metadata.

Document metadata — the hidden properties embedded in every DOCX, PDF, and image file — has been a standard tool in investigative journalism and legal discovery for over two decades. It has exposed plagiarism, revealed anonymous authors, confirmed or contradicted claimed timelines, and, in well-documented cases, changed the outcome of political investigations.

Here's what it can tell you and how to check it.

### The Metadata Hidden in a Word Document

Every Microsoft Word file is actually a ZIP archive containing a folder of XML files. Three of those files are forensic goldmines.

The first, `docProps/core.xml`, records the name of whoever created the document, the name of whoever last edited it, how many times the document was saved, and the creation and modification timestamps. The second, `docProps/app.xml`, records which version of which word processor was used, and — often — the company name registered in that Office installation.

The third container is the document body itself, which may contain tracked changes: a record of every individual edit, attributed to the editor who made it, with a timestamp.

And then there are embedded images. Photos embedded in a DOCX carry their own EXIF metadata. A photo taken on a phone carries GPS coordinates. If someone embedded a photo of a sensitive document into a Word file and sent it to you, the EXIF data in that photo may reveal where they were standing when they took it.

### The Metadata Hidden in a PDF

PDF metadata lives in two places that sometimes disagree with each other.

The info dictionary holds basic fields: `Producer` (which software created the PDF), `Creator` (which application generated the source document), `Author`, `CreationDate`, and `ModDate`.

The XMP packet, embedded in the file body as XML, holds a more verbose version of the same fields, plus GUIDs called `DocumentID` and `InstanceID` that can, in principle, link multiple versions of the same document to each other.

The `Producer` field tends to be the most useful for quick assessment. A document that claims to have been printed by a specific government agency, but whose `Producer` field says it was generated by LibreOffice Writer on a Linux machine, is raising a question worth pursuing.

### The 2002 Iraq Dossier

The best-known application of document metadata forensics in British politics involved a 2002 UK government document arguing that Iraq possessed active weapons of mass destruction.

After the document's publication, researchers examining its revision history and author fields found that the `lastModifiedBy` fields pointed to Downing Street communications staff. A textual comparison revealed that substantial portions of the document had been copied verbatim — including typographical errors — from an unpublished thesis by an academic named Ibrahim al-Marashi.

### Running Your Own Forensic Check

You do not need specialized forensics software for basic document metadata inspection. [MetaScrub](https://metadatafinder.com) handles it from the command line or the browser.

From the browser: drag a file onto [metadatafinder.com](https://metadatafinder.com). Nothing is uploaded — processing happens locally in your browser.

From the command line:

```bash
npm install -g metascrub

# Capture metadata immediately upon receiving a document
metascrub view --json suspicious-document.pdf

# Compare two versions to find what changed
metascrub compare version-a.docx version-b.docx

# Process a collection of related documents
metascrub batch ./documents/ --format json > all-metadata.json
```

The compare command is particularly useful for leak investigations: it shows not just what fields changed between versions, but which fields are present in one version and absent in the other.

### What Metadata Cannot Prove

Metadata can be altered. A sophisticated forgery will have consistent, plausible-looking metadata. The presence of correct-looking metadata does not confirm authenticity.

Timestamps reflect device clocks, which can be wrong, set to the wrong timezone, or deliberately manipulated.

Metadata forensics is a starting point for investigation, not a conclusion. Its value is in surfacing discrepancies that prompt further reporting.
